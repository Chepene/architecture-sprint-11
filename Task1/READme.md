## Анализ проблемных мест

| №  | Проблемное место                                      | Описание                                                                                       |
|----|------------------------------------------------------|------------------------------------------------------------------------------------------------|
| 1  | Перегруженный DWH                                   | Весь бизнес работает через один SQL Server DWH, он хранит и финансы, и медицину, и кадры, и отчёты — нагрузка огромная, производительность падает. |
| 2  | Сложные и долгие отчёты                             | Даже простые отчёты строятся часами, что тормозит принятие решений и снижает гибкость бизнеса. |
| 3  | Отсутствие самообслуживания для бизнес-пользователей | Аналитики и менеджеры не могут сами собрать отчёты или запросы — им нужны программисты или ИТ-отдел. |
| 4  | Жёсткая связка с легаси-решениями                   | Power Builder напрямую работает с DWH, его сложно масштабировать, обновлять или заменять.      |
| 5  | Невозможность быстро интегрировать новые бизнесы    | Когда компания покупает новые бизнесы (например, фарму или финтех), их интеграция требует долгой доработки DWH. |
| 6  | Отсутствие распределённого владения данными         | Все данные централизованы, доменные команды (медицина, финансы, ИИ) не управляют своими данными как продуктами. |
| 7  | Высокие риски из-за устаревших технологий           | DWH построен на SQL Server 2008, Power Builder морально устарел — это создаёт риски падений, потери поддержки и роста стоимости сопровождения. |
| 8  | Сложность масштабирования                          | С ростом данных SQL Server DWH не масштабируется горизонтально, а покупка оборудования или лицензий — дорого. |

## Приоритизация проблем (MoSCoW)

| Приоритет | Проблемное место                                      | Почему это важно                                                     |
|-----------|--------------------------------------------------------|----------------------------------------------------------------------|
| Must have (обязательно) | Перегруженный DWH | Без разгрузки DWH отчёты будут тормозить, бизнес потеряет управляемость. |
| Must have (обязательно) | Сложные и долгие отчёты | Бизнес не может быстро принимать решения.                          |
| Must have (обязательно) | Отсутствие самообслуживания | Блокируется рост аналитики, возрастает нагрузка на ИТ.              |
| Must have (обязательно) | Невозможность быстро интегрировать новые бизнесы | Без этого компания теряет конкурентоспособность.                  |
| Should have (желательно) | Жёсткая связка с легаси-решениями | Усложняет развитие, но не блокирует работу здесь и сейчас.         |
| Should have (желательно) | Отсутствие распределённого владения данными | Замедляет внедрение Data Mesh и усложняет масштабирование.         |
| Could have (можно улучшить) | Высокие риски из-за устаревших технологий | Можно оставить на время, но с рисками, если нет бюджета.          |
| Could have (можно улучшить) | Сложность масштабирования | Проблема на рост, но не критична на старте перехода.               |
